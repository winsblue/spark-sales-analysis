# 一、需求分析

> 项目：基于 Spark 的电商商品销售离线分析与 Java 服务化应用
> 项目编号：生产实习实践项目 3
> 达成层级：基础层（合格）+ 提高层（良好）

---

## 1. 项目背景

某电商平台日常运营中积累了大量的订单交易数据。业务方（运营部门）目前面临三个现实问题：

1. **数据分散**：订单明细、商品信息分散在不同系统中，缺少统一的统计口径，同一份"销售额"往往出现几个不同的数字；
2. **缺乏多维视角**：只能看到"总销售额"，无法回答"哪个类目在哪个渠道卖得好"这类经营决策问题；
3. **响应慢**：运营临时要看某个时间段、某个渠道的数据，需要数据人员临时跑脚本，无法自助查询。

因此需要建设一个**离线销售分析平台**：把分散的原始数据经过清洗、规整后统一沉淀，产出稳定口径的经营指标，
再通过 Web 看板让运营可以自助筛选、下钻与导出。

## 2. 项目目标

| 目标类型 | 具体描述 |
| --- | --- |
| 数据目标 | 建立 ODS / DWD / ADS 三层数据链路，脏数据可识别、可追溯，指标口径唯一 |
| 计算目标 | 使用 Spark 完成中等规模数据集（20 万行级）的清洗与多维统计，并比较不同计算方式的运行效果 |
| 服务目标 | 使用 Spring Boot 把统计结果服务化，提供稳定、统一的 RESTful 接口 |
| 展示目标 | 使用 Vue3 完成可视化看板，支持条件筛选、图表联动、明细下钻与数据导出 |
| 工程目标 | 形成可重复运行、可交付、有文档的完整工程 |

## 3. 用户角色与使用场景

| 角色 | 关注点 | 典型操作 |
| --- | --- | --- |
| 运营人员 | 本期卖了多少、哪类商品好卖、哪个渠道效率高 | 打开看板 → 选择时间范围与渠道 → 查看指标卡与图表 → 下钻明细 |
| 数据分析师 | 指标口径是否一致、趋势是否异常 | 查看数据质量报告、一致性校验结果，导出明细做二次分析 |
| 数据工程师 | 作业是否按预期产出、脏数据有多少 | 查看作业运行日志与清洗规则命中统计 |
| 后端开发 | 接口稳定性与查询性能 | 查看接口文档、校验接口返回 |
| 指导教师 / 答辩评委 | 技术路线是否完整、代码是否规范 | 查看代码结构、文档、演示系统 |

## 5. 功能性需求

### 5.1 数据管理需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | 支持将原始订单明细、商品维度数据导入原始层（ODS），保留原始值不做加工 | 高 |
| FR-02 | 支持对原始数据进行清洗：空值填充、完全重复记录去重、时间格式规整、数量与单价合法性校验、实付金额一致性校验、订单状态标准化 | 高 |
| FR-03 | 支持记录被丢弃的异常数据及其违反的规则，做到可追溯 | 中 |
| FR-04 | 支持输出数据质量统计：原始记录数、各规则命中数、有效记录数、质量得分 | 中 |
| FR-05 | 支持按批次号标识每次运行的数据，支持重复运行且结果可复现 | 高 |

### 5.2 指标计算需求

| 编号 | 指标 | 口径定义 | 优先级 |
| --- | --- | --- | --- |
| MR-01 | GMV（成交金额） | 有效订单（已完成 / 已支付）的实付金额之和 | 高 |
| MR-02 | 下单量 | 去重后的订单编号数量（含待付款、取消、退款订单） | 高 |
| MR-03 | 有效订单量 | 订单状态为已完成或已支付的订单数量 | 高 |
| MR-04 | 销售件数 | 有效订单中的商品购买数量之和 | 高 |
| MR-05 | 下单用户数 | 产生有效订单的去重用户数量 | 高 |
| MR-06 | 客单价 | GMV ÷ 有效订单量 | 高 |
| MR-07 | 件单价 | GMV ÷ 销售件数 | 中 |
| MR-08 | 退款率 | 退款订单量 ÷ 下单量 | 中 |
| MR-09 | 折扣率 | 优惠金额 ÷ 原价金额（数量 × 单价） | 中 |
| MR-10 | 多维分布 | 按类目 / 商品 / 渠道 / 支付方式 / 省份 / 渠道×类目 分组统计 GMV、件数、订单量、用户数 | 高 |
| MR-11 | 时间趋势 | 按天统计上述核心指标 | 高 |

### 5.3 服务与展示需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| SR-01 | 提供核心指标概览接口，返回 9 项指标 | 高 |
| SR-02 | 提供趋势接口，按天返回指标序列 | 高 |
| SR-03 | 提供类目 / 商品 / 渠道 / 支付方式 / 省份 的排行与分布接口，支持 TopN 与占比 | 高 |
| SR-04 | 提供渠道×类目交叉对比接口，支持分组对比 | 中 |
| SR-05 | 提供明细下钻接口，支持分页与多条件筛选 | 高 |
| SR-06 | 提供明细 CSV 导出功能 | 中 |
| SR-07 | 提供运行监控接口：数据质量报告、作业运行记录、数据一致性校验 | 中 |
| SR-08 | 前端支持时间范围、渠道、类目等条件筛选，筛选后所有图表与明细联动刷新 | 高 |
| SR-09 | 前端提供指标卡、折线图、柱状图、饼图、排行图与明细表格 | 高 |
| SR-10 | 前端提供运行监控页，展示数据质量、计算方式性能对比与一致性校验结果 | 中 |
| SR-11 | 提供在线接口文档 | 低 |

### 5.4 明确不在本期范围（属拓展层，按要求不实现）

- 实时数据接入（Kafka / Flink）
- 用户权限与角色化看板
- 定时调度与任务编排
- 结果缓存与查询性能优化
- 数据倾斜调优、分区与并行度优化

## 6. 非功能性需求

| 类别 | 要求 | 本项目落地措施 |
| --- | --- | --- |
| 性能 | 单次离线计算在 5 分钟内完成 20 万行数据处理 | Spark local[*] 使用全部 CPU 核；结果表批量写入并开启 `rewriteBatchedStatements` |
| 性能 | 看板接口响应时间不超过 1 秒 | 常规视图读取 ADS 预计算表；明细表按 `stat_date`、渠道、类目等建立索引 |
| 数据准确性 | 指标结果与明细汇总结果必须一致 | 提供一致性校验接口，自动比对预计算值与明细汇总值 |
| 可重复性 | 同一份数据重复运行结果完全一致 | 模拟数据生成器固定随机种子；每次运行先清空目标表；所有计算结果可追溯到批次号 |
| 可追溯性 | 被丢弃的异常数据可查 | `dwd_clean_reject` 表记录规则编码、原始记录片段与批次号 |
| 数据合规 | 不采集、不展示真实个人信息 | 全部数据为程序模拟生成，用户标识为脱敏编号（`U000001` 形式） |
| 可维护性 | 表结构与列顺序集中定义，避免写入错位 | `Schemas` 常量类统一维护；SQL 集中在 Mapper XML |
| 兼容性 | 适配存量数据库环境 | 兼容 MySQL 5.5，字符集使用 `utf8`（5.5 不支持 utf8mb4） |
| 易用性 | 项目可一键运行 | 提供 `scripts` 一键脚本，作业自动建库建表；配套 README 说明 |

## 7. 系统边界与约束

- **输入**：数据源为程序模拟生成的 CSV 文件（模拟企业数据落地的常见形态）；
- **输出**：MySQL 中的 14 张结果表 + Web 可视化看板 + CSV 导出文件；
- **约束**：
  1. 后端必须采用 Java 技术体系（Spring Boot / Spring MVC）；
  2. 大数据处理需使用 Hadoop / HDFS / Hive / MapReduce / Spark / Flink / Kafka 等组件之一；
  3. 需完成"数据上传（导入）— 处理— 分析— 展示"的完整链路；
  4. 只实现基础层与提高层，不实现拓展层。

## 8. 技术选型说明

| 决策点 | 备选方案 | 最终选择 | 选择理由 |
| --- | --- | --- | --- |
| 大数据计算引擎 | Hadoop MapReduce / Hive / Spark / Flink | **Spark 3.5.1** | Spark 支持单机模式，无需部署 Hadoop 集群即可运行；同时提供 RDD 与 DataFrame 两套 API，天然满足提高层"比较不同处理方式"的要求；SparkSQL 贴近分析场景 |
| 结果存储 | Hive / MySQL | **MySQL** | 后端服务需要低延迟点查，MySQL 更合适；Hive 适合大批量离线分析但不适合接口直接查询 |
| 后端框架 | Spring MVC / Spring Boot | **Spring Boot 2.7.18** | 内嵌容器、自动装配，工程化程度高；2.7 是支持 JDK 8 的最后一个分支，匹配实训环境 |
| 持久层 | JPA / MyBatis-Plus | **MyBatis-Plus** | SQL 可控，便于按条件拼装多维查询；分页插件成熟 |
| 前端框架 | 原生 HTML / jQuery / Vue | **Vue 3 + ECharts** | 组件化开发，ECharts 图表能力完善，符合企业主流技术栈 |
| 计算路径 | 全预计算 / 全即席查询 | **预计算 + 即席查询混合** | 预计算保证看板首屏速度，即席查询保证任意维度组合下的筛选联动正确，同时避免维度组合爆炸 |
