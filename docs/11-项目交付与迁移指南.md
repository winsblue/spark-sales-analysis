# 十一、项目交付与迁移指南

> 场景：把这个项目复制到**另一台电脑**（同学/老师/面试演示机/你的新电脑）。
> 本文给出「怎么打包 → 对方装什么 → 对方怎么跑 → 会踩什么坑」的完整答案。

---

## 0. 先分清场景，再看方式

**不同接收方需要的东西差别很大**，先对号入座，别一股脑把整个文件夹拷过去（`node_modules` 就有 95 MB 是垃圾）。

| 场景 | 接收方需要 | 推荐方式 | 包大小 |
| --- | --- | --- | --- |
| **A. 交给老师 / 交作业** | 源码 + 文档 + 开发过程 | **源码包（含 `.git`）** | **约 2 MB** |
| **B. 同学想在自己电脑跑起来** | 上面 + 能运行 | **源码包 + 预构建 jar + 数据库快照** | 约 45 MB |
| **C. 面试现场演示** | 5 分钟内看到界面 | **免构建包**（只需 JDK + MySQL） | 约 45 MB |
| **D. 换台电脑继续开发** | 源码 + 开发环境 | `git clone`（最推荐） | 约 2 MB |
| **E. 只给人看代码** | 源码 | 发 GitHub 链接即可 | 0 |

## 1. 方式对比：Git 克隆 vs 压缩包

| | **git clone**（推荐 A/D 场景） | **压缩包**（推荐 B/C/E 场景） |
| --- | --- | --- |
| 内容 | 只有被 Git 跟踪的文件（自动排除构建产物） | 你自己决定放什么 |
| 开发历史 | ✅ 完整 48 条提交 | 只有把 `.git` 一起打包才有 |
| 后续更新 | `git pull` 就能同步 | 要重新拷 |
| 需要网络 | 需要（GitHub 直连或代理） | 不需要 |
| 能带改动 | 不能（未提交的改动不会传） | 能 |
| 适合 | 继续开发、给老师看过程 | 交运行包、没网环境、面试演示 |

> **结论**：**两个都给**是标准做法 —— 把 GitHub 链接写进交付说明，同时附一个离线压缩包。

## 2. 交付包里放什么、不放什么

### ✅ 要放

| 内容 | 为什么 |
| --- | --- |
| 源码（`spark-job/` `server/` `web/` 的 `src`） | 核心 |
| `docs/` 全部文档（01~11） | 交付物主体 |
| `sql/01_schema.sql` | 建库脚本 |
| `scripts/`（含 `linux/`） | 一键脚本 |
| `README.md`、`pom.xml`、`.gitignore`、`.gitattributes` | 工程配置 |
| `data/sample/*.csv`（2 个样例文件） | 让对方看懂数据长什么样 |
| **`.git/`（仅 0.49 MB）** | 48 条提交历史，交作业时是加分项 |
| **预构建 jar**（可选） | 让对免除"装 Maven 构建"这一步 |
| **数据库快照**（可选） | 让对免除"跑 Spark 作业"这一步 |

### ❌ 不要放

| 内容 | 大小 | 为什么不放 |
| --- | --- | --- |
| `web/node_modules/` | **约 95 MB** | 对方 `npm install` 就能生成 |
| `web/dist/` | 约 1 MB | 构建产物，且已打进后端 jar |
| `spark-job/target/` `server/target/` 里的**中间文件** | — | 只保留要交付的 jar |
| `data/raw/*.csv` | **约 25 MB** | 数据可随机生成（固定种子，结果一致） |
| `server/src/main/resources/static/` | — | 前端构建产物，已打进 jar |
| IDE 配置（`.idea/` `.vscode/` `*.iml`） | — | 个人偏好，且路径含本机信息 |
| `*.log`、临时文件 | — | 无意义 |

> **一句话记法**：**能被命令重新生成的东西，都不放。**

## 3. 生成交付包（三种方法）

### 方法 A：从 GitHub 拉（最干净，推荐）

```bash
git clone https://github.com/winsblue/spark-sales-analysis.git
```

Git 只会检出被跟踪的文件，`.gitignore` 里的构建产物自动排除 —— **天然就是干净的源码包**。
接收方拿到后就是 48 条提交的完整仓库。

### 方法 B：一键打包脚本（推荐，会带上预构建产物）

```powershell
cd C:\Users\19351\WorkBuddy\2026-09-21-11-34-32\spark-sales-analysis
powershell -ExecutionPolicy Bypass -File scripts\package-dist.ps1
```

产物：`dist/spark-sales-analysis-delivery_<日期时间>.zip`，**实测 45.35 MB**，内含

```
spark-sales-analysis-delivery_<时间戳>/
├── 交付说明.md                      ← 给对方看的快速上手（3 步跑起来）
├── spark-sales-analysis/            ← 干净源码（含 .git，48 条提交）
│   ├── docs/01 ~ 11                 ← 全部文档
│   ├── spark-job/ server/ web/      ← 三个模块源码
│   └── scripts/                     ← 一键脚本（含本打包脚本）
└── prebuilt/                        ← 免构建运行（-SourceOnly 时不生成）
    ├── sales-analysis-server.jar    ← 直接 java -jar 起后端（29 MB，已含前端页面）
    ├── spark-job-1.0.0-cluster.jar  ← 集群提交用（1 MB）
    └── sales_analysis-dump.sql.gz   ← 数据库快照（17 MB，含 19.3 万行明细与全部结果表）
```

> 打包脚本会自动做这些事：排除 `node_modules` / `dist` / `target` / `data/raw` /
> IDE 配置 / 日志，保留 `.git`，带上已构建的 jar 与数据库快照，并复制一份「交付说明.md」。
> 其中 **`data/raw` 必须排除**（约 25 MB，重复打包会白白让包大一倍，且可随机生成）。

### 方法 C：手动压缩（不推荐，容易漏或多）

如果非要用资源管理器右键压缩，**至少先做这两件事**：

```powershell
# 1) 删掉占用空间大又能重建的目录（用 Python 删，比 Remove-Item 可靠）
python -c "import shutil; [shutil.rmtree(p, ignore_errors=True) for p in ['web/node_modules','web/dist','data/raw']]"
# 2) 确认工作区干净（有未提交改动要一起带走就提交，或提醒对方这是工作版本）
git status --short
```

## 4. 接收方电脑需要装什么

### 按场景分

| 组件 | 版本要求 | 免构建运行(C) | 源码构建(B) | 开发(D) |
| --- | --- | --- | --- | --- |
| **JDK** | **8**（11/17 也能跑后端；Spark 3.5 支持 8/11/17） | 必需 | 必需 | 必需 |
| **MySQL** | 5.5 ~ 8.x 都行（见第 7 节坑 1） | 必需 | 必需 | 必需 |
| Maven | 3.6+ | ❌ 不需要 | 必需 | 必需 |
| Node.js | 18+ | ❌ 不需要 | 仅重建前端时需要 | 需要 |
| Spark | 3.5.x | ❌ 不需要 | 跑作业必需 | 跑作业必需 |
| winutils | — | ❌ | Windows 跑 Spark 必需 | 同上 |

### 环境自检命令（让对方先跑这几条）

```bash
java -version                    # 期望 1.8.x（或 11/17）
mvn -version                     # 只用源码构建时才需要
node -v                          # 只有要重建前端才需要
git --version
mysql -uroot -p -e "SELECT VERSION();"
```

### 三个环境的安装要点

| 组件 | 要点 |
| --- | --- |
| **JDK 8** | 推荐 Oracle JDK 8u212 或 Adoptium Temurin 8。**装完配 `JAVA_HOME`** |
| **MySQL** | 5.5 / 5.7 / 8.x 均可。8.x 需注意认证插件（见坑 1）；字符集用 `utf8` 即可 |
| **Maven** | 解压即用，配 `MAVEN_HOME` + PATH；`settings.xml` 建议配阿里云镜像（否则下载依赖很慢）|
| **Spark** | Windows 需额外放 `winutils.exe` + `hadoop.dll` 并配 `hadoop.home.dir`；Linux 用 `scripts/linux/setup-spark.sh` |

> **Maven 阿里云镜像配置**（对方如果没配，构建会慢到怀疑人生）：
> ```xml
> <!-- ~/.m2/settings.xml -->
> <mirror>
>   <id>aliyun</id>
>   <mirrorOf>central</mirrorOf>
>   <url>https://maven.aliyun.com/repository/public</url>
> </mirror>
> ```

## 5. 接收方的操作步骤

### 路线 1：免构建运行 —— 只要 JDK + MySQL（约 5 分钟）

适合"只想看看长什么样"的场景。

```bash
# ① 恢复数据库快照（如果交付包里带了）
gunzip < prebuilt/sales_analysis-dump.sql.gz | mysql -uroot -p
# Windows 下： 先把 .gz 解压成 .sql，再执行
#   mysql -uroot -p < sales_analysis-dump.sql

# ② 启动后端（jar 里已经包含前端页面，不需要 Node）
java -jar prebuilt/sales-analysis-server.jar

# ③ 浏览器打开
#   看板：  http://localhost:8080/
#   接口文档：http://localhost:8080/swagger-ui.html
```

**注意**：快照里的数据是"某次运行的结果快照"；如果只想看界面，这样最快。

### 路线 2：从源码完整跑一遍（约 30 分钟，含依赖下载）

适合"想真正跑通全流程"的场景。

```bash
# ① 建库建表（也可以跳过，作业会自动建）
mysql -uroot -p < sql/01_schema.sql

# ② 改配置：数据库地址与口令（两处都要改）
#    spark-job/src/main/resources/spark-job.properties  → jdbc.url / jdbc.user / jdbc.password
#    server/src/main/resources/application.yml          → spring.datasource.url / username / password

# ③ 构建
mvn -B clean package -DskipTests

# ④ 准备数据（两条路选一条）
#    A. 真实数据（推荐）：Olist 巴西电商公开数据集
powershell -ExecutionPolicy Bypass -File scripts\download-real-data.ps1   # 下载约 48 MB
scripts\run-etl.cmd --import-real                                         # 转为 ODS 标准格式
#    B. 模拟数据：20 万行 + 8 类脏数据
scripts\run-etl.cmd --generate

# ⑤ 跑离线作业（数据源由 spark-job.properties 的 data.raw.dir 决定）
scripts\run-etl.cmd --mode=both

# ⑥ 启动后端
scripts\start-server.cmd
# 或者：java -jar server/target/sales-analysis-server.jar

# ⑦（可选）重建前端
cd web && npm install && npm run build
# 然后把 web/dist/* 拷到 server/src/main/resources/static/，重新打包 server
```

> ⚠️ **切换数据源时别忘了同步货币单位**：真实数据是巴西雷亚尔（BRL），模拟数据是人民币（元）。
> 两处要一起改：`spark-job.properties` 的 `data.currency.unit` 与 `application.yml` 的 `app.currency.unit`。

> **作业会自动建库建表**（`SchemaInitializer` 执行 `sql/01_schema.sql`），
> 所以第 ① 步不是必须的 —— 但要保证 MySQL 账号有 `CREATE DATABASE` 权限。

### 路线 3：部署到 Linux（集群环境）

见 `docs/09-Linux集群部署指南.md`，里面有完整步骤 + 针对你本机 VM 的实测参数。

## 6. 数据库怎么一起给

| 方式 | 命令 | 体积 | 适用 |
| --- | --- | --- | --- |
| **A. 导出快照**（推荐） | `mysqldump -uroot -p sales_analysis > dump.sql` | 约 35 MB（gzip 后约 5 MB） | 免构建运行、现场演示 |
| **B. 让对方重跑作业** | 什么都不用给 | 0 | 对方有完整环境，且想验证全链路 |
| **C. 只给表结构** | 给 `sql/01_schema.sql` | 17 KB | 只要空表 |

**A 的操作细节**：

```bash
# 导出（含建库语句，对方可直接导入）
mysqldump -h 127.0.0.1 -uroot -p123456 --databases sales_analysis --default-character-set=utf8 > sales_analysis-dump.sql

# 压缩（35MB → 约 5MB）
gzip sales_analysis-dump.sql

# 对方导入
mysql -uroot -p < sales_analysis-dump.sql
```

> ⚠️ 用 `--databases` 参数会把 `CREATE DATABASE` 一起导出，对方不用先建库。
> ⚠️ 加 `--default-character-set=utf8` 避免中文乱码。

## 7. 五个必踩的坑（按被坑概率排序）

### 坑 1：对方是 MySQL 8，后端连不上（最常见）

**现象**：`Unable to load authentication plugin 'caching_sha2_password'`

**原因**：本项目适配 MySQL 5.5，驱动锁的是 `mysql-connector-java 5.1.49`；
MySQL 8 默认用 `caching_sha2_password` 认证插件，5.1.x 驱动不支持。

**三种解法**（任选其一）：

```sql
-- 解法 A（最快）：把账号改成旧认证插件
ALTER USER 'root'@'%' IDENTIFIED WITH mysql_native_password BY '你的口令';
FLUSH PRIVILEGES;
```

```xml
<!-- 解法 B：升级驱动到 8.x（改 spark-job/pom.xml 与 server/pom.xml） -->
<artifactId>mysql-connector-java</artifactId>
<version>8.0.33</version>
<!-- 同时把 application.yml 的 driver-class-name 改成 com.mysql.cj.jdbc.Driver
     并在 URL 加 allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai -->
```

**解法 C**：让对方装 MySQL 5.7（最省事，5.7 默认还是 native password）。

### 坑 2：对方 MySQL 口令不同

`jdbc.password` 出现在**两个文件**里，都要改（只改一个的话，作业能跑但后端连不上，或反过来）：

- `spark-job/src/main/resources/spark-job.properties`
- `server/src/main/resources/application.yml`

### 坑 3：Windows 上跑 Spark 报 `winutils.exe` 找不到

**现象**：`java.io.FileNotFoundException: Could not locate Hadoop executable: ...\winutils.exe`

**解法**：下载 `winutils.exe` + `hadoop.dll`（版本对应 Hadoop 3.x）放到某个目录，
然后在 `spark-job.properties` 里填 `hadoop.home.dir` 并把它加到 PATH。

### 坑 4：8080 端口被占用

```bash
# 查占用
netstat -ano | findstr :8080
# 换端口启动
java -jar sales-analysis-server.jar --server.port=8081
```

> 注意：如果机器上有环境变量 `SERVER__PORT`（某些工具会注入），Spring Boot 的宽松绑定会覆盖
> `application.yml` 里的配置，导致端口不是 8080。想强制就用命令行参数覆盖。

### 坑 5：中文乱码

| 位置 | 检查点 |
| --- | --- |
| 数据库 | 建库语句里是 `DEFAULT CHARSET=utf8`；表也是 `utf8` |
| 导入 dump | 导出的 mysql 命令要加 `--default-character-set=utf8` |
| 导出 CSV | 后端已写入 UTF-8 BOM，Excel 打开不乱码 |
| 控制台显示 | Windows cmd 默认 GBK，看到乱码不代表数据错（用 `chcp 65001` 切 UTF-8）|

## 9. 一分钟速查：我要复制给别人，具体做什么

```powershell
# 场景 A：交给老师
#   方式一：把 GitHub 链接发过去（推荐）
#   方式二：打包源码（含 .git）
cd C:\Users\19351\WorkBuddy\2026-09-21-11-34-32\spark-sales-analysis
powershell -ExecutionPolicy Bypass -File scripts\package-dist.ps1 -SourceOnly

# 场景 B/C：对方要跑起来（含预构建 jar + 数据库快照）
powershell -ExecutionPolicy Bypass -File scripts\package-dist.ps1

# 场景 D：换台电脑继续开发
git clone https://github.com/winsblue/spark-sales-analysis.git
```

生成的 zip 里带一份 `交付说明.md`，对方照着走就能跑起来 —— **你不用另外解释**。
